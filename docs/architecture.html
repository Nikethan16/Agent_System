Turn pipeline — runs per user message over the WebSocket

Trigger: {"type":"run", text, max_usd, max_iterations, mode, plan_first, review, stream} on /api/ws/{session_id} · returns a live stream of events + a final answer

1

Accept run · build Budget + ApprovalBroker · spawn a worker thread

server/api/ws.py

  • Budget(max_usd, max_iterations) from the UI caps · ApprovalBroker(mode) for the gate
  • The agent run is synchronous → runs in a daemon thread; events bridge to the async socket via a thread-safe asyncio.Queue
  • Stop = set budget.max_iterations = iterations → next check() halts the run cooperatively
2

Checkpoint the workspace · save the message

server/chat.py → server/db.py

  • create_checkpoint() · copytree snapshot of data/workspaces/<session> before the turn → user can rewind
  • Persist the user message to SQLite (WAL mode + 30 s busy-timeout so worker + API don't collide)
3

Assemble context (so it feels like a conversation)

chat.py: run_turn

  • Last 6 turns of history + cross-session memory recall (top-k notes from other chats)
  • + Project instructions/knowledge files · + attachment text (PDFs text-extracted via pypdf)
  • Enter the session's isolated sandbox: using_workspace(data/workspaces/<session>) (a contextvar)
4

Classify & route — cheap tier-1 model call

core/router.py: classify → emits route

  • Returns {tier:1|2|3, task_type, requires_web, reason} · JSON-only · falls back to a safe tier on junk
  • Category exposed as task_type (never a bare type) so spreading into the event can't clobber it
5

Branch by difficulty

core/orchestrator.py: handle_task

  • tier 1-2 → the dispatcher picks ONE specialist (select_agent) → emits assign → that agent's own loop (step 6)
  • tier 3 → the LEAD master loop (see the second pipeline below) — todos + delegation
  • plan-first mode → emit the plan and stop for approval; approval re-enters with subtasks=[…]
6

Specialist agent loop — think → act → observe

core/agent.py: run_agent · model = registry.model_for_tier(tier, task_type)

  • Only the agent's allowed tools are offered (least privilege, from config/agents.yaml)
  • Relevant Skills are auto-selected, staged into ./.skills/, and injected → emits skill
  • Emits thought / tool events; after MAX_TOOL_ROUNDS=8 tools are dropped to force a final answer
  • Provider error / rate-limit → graceful message, not a crash (LiteLLM num_retries=3 first)
7

Every tool call passes the security gate

core/agent.py: _run_one_tool → core/policy.py / server/approvals.py

  • Deterministic policy gate: hard_block → block · critical/require_human → escalate · else allow
  • Escalation → security-manager agent (approve/deny) → maybe a human Approve/Deny card (worker blocks on a threading.Event)
  • Sandboxed execution; every decision appended to audit.log (full detail in the 3rd pipeline)
8

Auto-QA (critic) — concrete pass/fail, one retry

orchestrator._auto_review · tri-state review = auto / force-on / off

  • On by default for tier-3 and tier-2 coding/writing/data/math · skipped for trivial + look-up tasks
  • critic agent returns strict pass/fail JSON (never a 1-10 score) → emits critic
  • On fail → the same agent gets the issues back as feedback and fixes them once
9

Persist · stream · remember

chat.py → db.py / memory.py / trace.py

  • Final answer streamed as token events + emitted as final (with run cost)
  • Saved to SQLite (message + cost + every event); written to data/traces/<session>.jsonl
  • Remember "Request → Outcome" for future cross-session recall · run_complete closes the socket turn

LEAD master loop — runs for complex (tier-3) tasks · Claude-Code-style single-threaded supervisor

core/orchestrator.py: _master_loop · the LEAD keeps a live todo list and DELEGATES scoped steps to specialists (depth-limited)

1

Build the lead · seed an explicit plan

  • LEAD uses a reasoning-tier model · system prompt embeds the live agent menu + skills menu
  • _make_plan asks a tier-3 model for 3-6 ordered steps → emits plan with the todo list (guarantees a visible breakdown)
2

Loop — the lead works the plan (≤ MAX_MASTER_ROUNDS = 16)

Meta-tools available to the lead each round:

  • write_todos — create/update the plan → re-emits plan
  • delegate(agent, instruction, skill?) — hand a scoped step to a specialist
  • read_file / list_files / write_file / run_bash — small steps the lead does itself
3

Delegate → a specialist subagent runs (depth-limited)

emits assign · MAX_DELEGATIONS = 10 · subagents CANNOT delegate again

  • Agent chosen by id (or keyword fallback) · runs its own think→act→observe loop with its own tools
  • Gets the blackboard digest (earlier results) as context · can load the named skill (docx/xlsx/pptx/pdf/…)
  • Result posted back to the shared Blackboard for downstream steps
4

Reminder injection — keep the plan in front of the model

  • After each round the current todo list is re-appended to the messages → the lead never loses track
  • (This is the key trick that makes "break down the task and stay on it" reliable on weaker models)
5

Finish

  • LEAD replies with no tool call → that text is the final answer (mentions files produced)
  • Budget exhausted mid-flight → _finalize_from_board synthesizes an answer from the blackboard so you still get output

Security gate — runs before any risky tool executes · defense in depth

Single hook approve(tool, args, decision) in the agent loop · every decision is audited · irreversible actions need BOTH the manager agent AND a human

0

Least privilege (config)

  • Each agent only holds the tools listed for it in config/agents.yaml · the doc agent literally cannot run shell; only coder/frontend can
1

Tool risk label (config)

  • safe (read/list/search) · write (write_file) · critical (run_bash, deletes, deploys) · plus a requires_human flag
2

Deterministic policy gate (no model)

core/policy.py + config/policy.yaml

  • hard_block pattern (e.g. rm -rf /, fork bombs) → BLOCK · zero LLM cost
  • require_human pattern OR a critical tool → ESCALATE · else ALLOW
3

Security-manager agent (Layer 3)

server/approvals.py: _manager_review

  • Reviews the action in context → approve/deny + reason · fails closed (denies) if it can't decide · skipped only in trusted mode
4

Human Approve / Deny (Layer 4)

emits approval_request → UI card → approval_response

  • Always in careful mode · only for requires_human actions in auto mode · never in trusted
  • Worker thread blocks on a threading.Event until you click (or 300 s timeout → deny)
5

Audit (always)

  • Every allow / deny / block is appended to audit.log (agent · tool · args · decision · reason) — nothing destructive happens silently

Design decisions a reviewer might probe

DecisionRationale
Single model-call point + Budget capsEvery call enforces max_usd + max_iterations centrally · no code path can loop or spend uncapped (the #1 invariant)
Cost-first "cheapest" selectorAuto-picks the cheapest available + capable model · add a free key and free models unlock automatically · no hardcoded names
Supervisor + blackboard (not free-form A2A)Agents collaborate through a coordinator + shared scratchpad · loop-safe + budget-safe + traceable (free agent-to-agent chatter is the #1 cause of runaway cost)
Master loop with reminder injectionRe-showing the todo list each round keeps weaker models on-plan · depth-limited delegation prevents runaway subagent spawning
Deterministic policy gate before the LLM gateCatches obvious danger (rm -rf, DROP TABLE) at zero cost; the manager agent + human handle the judgment calls
WebSocket (not SSE)Chat needs two-way: stream events out AND receive approvals / stop in
SQLite + per-session workspacesOne file, no extra server · isolated on-disk artifacts per chat · WAL handles worker + API concurrency
Contextvar sandbox rootPer-session workspace without changing the containment check — tools stay sandboxed, only the location is per-session
Skills via progressive disclosureOnly name+description scanned until relevant; full body + scripts loaded on selection · drop-in from anthropics/skills
Critic judges concrete pass/fail"does it run? do tests pass? all requirements met?" — never a self-assigned 1-10 score
Local single-user app · runs at http://localhost:8800 from .venv on free models · engine stays offline + provider-agnostic · full write-up in docs/PROJECT_OVERVIEW.md
